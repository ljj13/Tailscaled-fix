# v1.102.5-dnsfix.2-webui.2

发布日期：2026-10-07 · 作者：FogPurification · arm64 · versionCode：110200504

本版正式发布 main 的网络诊断增强与 `90ff97a` 的 Android outer IPv6 routing
修复。Tailscale 基础版本仍为 v1.102.5，daemon 与 Android DNS helper 二进制
复用已验收的 dnsfix.2 版本。此次发布整理没有再修改网络逻辑。

## 更新内容

- 增强 selftest / diag 与 WebUI 网络详情：Self hostname/OS/Tailnet 地址、DERP
  地区、发布 endpoints、地址类型与接口、UDP listener、peer 在线状态和实际路径、
  netcheck UDP/IPv4/IPv6/NAT/PortMapping，以及 physical/VPN underlying/outer route。
  保留原始输出供复制；失败、缺字段和超时不会影响 daemon。
- 修复 Redmi outer IPv6：原 `0x10020000` mark 先命中 osrouter 的
  main/default/unreachable，而 Android 物理 IPv6 出口位于 netd policy table。
  真机 SELECT_NETWORK 返回 `0xf0070`，组合 mark `0x100f0070` 仍不可达，
  因此不改 socket mark，改为动态引用已验证的真实物理 IPv6 表。
- IPv6-only 的5209规则限定本地 bypass 流量；通过现有 Android discovery 跟随
  VPN underlying，核对实际 netId selector、接口公网 IPv6 与物理 default route。
  watchdog 自动更新或撤销旧规则，并在选网变化时触发有界 Re-STUN 发布正确 endpoint。
  不硬编码 netId，不复制 default 到 main，不强制 direct，继续保留 DERP fallback。
- 增加并发锁、规则归属检查、冲突诊断和 stop 清理；外来规则不被覆盖。
  `outer-ipv6-status`、webstatus、diag/selftest 保留当前 network/interface/table/reason。

## Redmi Note 8 Pro 真机结果

以下为修复时的 ADB / SSH 实测，完整证据见
[IPv6 marked routing 验收](../testing/IPV6_MARKED_ROUTING.md)。此次发布未重新切换手机网络。

| 环境 | 结果 |
|---|---|
| 移动数据 + FlClash ON，physical116 / ccmni3 | netcheck IPv4/IPv6=true，marked IPv6 route 正确，direct 43 ms |
| 移动数据 + FlClash OFF，确认无 VPN network | IPv4/IPv6=true，direct 37 ms |
| FlClash 再次 ON，VPN103→117，underlying116 | physical 选择正确，direct 70 ms |
| Wi-Fi→移动，physical119 / ccmni1 | watchdog 自动选表，IPv6=true，direct 80 ms |
| 移动→IPv4-only Wi-Fi，physical120 / wlan0 | 自动撤销5209，没有旧移动表残留；Running、IPv4正常，保留 DERP fallback |
| 再回移动，physical121 / ccmni3，FlClash ON | 自动恢复，UDP/IPv4/IPv6=true，direct 75 ms |

实际 direct endpoint：`[2001:250:3c00:3487:add3:4002:9c55:b820]:41641`。
tcpdump 确认 magicsock IPv6 UDP 从真实 ccmni3 发出；Re-STUN 后发布真实 IPv6
listener endpoint，恢复 direct。daemon PID 始终未重启，节点地址和身份保持不变。
最后一次切网的前两次 kernel ping 丢包，路径收敛后重测3/3成功，RTT 48.8–68.9 ms。
IPv4-only Wi-Fi 没有 IPv6 出口，不能据此要求 IPv6 direct；DERP 是正常兜底路径。

## 升级与兼容

覆盖安装 ZIP 后重启，无需卸载、退出登录或删除节点。安装器保留现有 state、
登录身份、settings.ini、手工 routes 和 hostname 保护标记；模块 ID 仍为 `tailscaled`。

保留 GOOS=linux reported OS、原 fwmark `0x10020000`、IPv4 main default route、
table52/1099、osrouter、Clash/Mihomo exemptions、DNS helper 和已有 WebUI 操作。
没有引入 userspace-networking、hev-socks5-tunnel 或其他代理层。
历史 dnsfix.2 的 Wi-Fi + FlClash DNS 共存验收仍保留；它与本次 IPv4-only Wi-Fi
的 IPv6 fallback 验证属于不同测试范围。

## 最少验证命令

在具有公网 IPv6 的移动网络下执行：

```sh
su -c 'cat /data/adb/tailscale/outer-ipv6-status'
su -c 'ip -6 route get 2001:250:3c00:3487:add3:4002:9c55:b820 mark 0x10020000'
su -c '/data/adb/tailscale/scripts/tailscaled.service selftest 100.72.239.86'
```

地址是此次验收目标，可替换成自己的 peer 公网 IPv6 和 Tailnet IP。
